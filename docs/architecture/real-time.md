# Real-Time Layer

WebSockets are a hard requirement of the brief — bids, chat, and countdown state must update
across every connected screen *"without refreshing"*.

## The Three Pieces

| Piece | Where it runs | Job |
|---|---|---|
| **Laravel Reverb** | `php artisan reverb:start` | WebSocket server holding open connections |
| **Laravel broadcasting** | The app | `broadcast(new BidPlaced($bid))` |
| **Laravel Echo** | Browser | Subscribes to channels, receives pushes |

Reverb speaks the Pusher protocol, so Echo works against it unchanged and swapping to hosted
Pusher later would be a config change rather than a rewrite.

The React side uses `@laravel/echo-react`, which wraps Echo in hooks — `useEchoPublic`,
`useEcho` (private), `useEchoPresence`, `useConnectionStatus`. `configureEcho({ broadcaster:
'reverb' })` runs once at the top of `app.tsx`.

## Running It

`composer run dev` starts four processes:

```
server   php artisan serve            :8000
queue    php artisan queue:listen
reverb   php artisan reverb:start     :8081
vite     npm run dev                  :5173
```

Reverb must be running for any real-time feature to work. Without it the app still serves pages —
events simply go nowhere, which makes the failure quiet and easy to misdiagnose.

## Port 8081, Not 8080

Reverb defaults to 8080, which on this machine is held by Oracle's TNS listener. The failure reads
as a permissions error rather than a busy port:

```
Failed to listen on "tcp://0.0.0.0:8080": An attempt was made to access a socket
in a way forbidden by its access permissions
```

Two environment variables control ports, and **both** must be set — changing only the second leaves
the server bound to the default:

| Variable | Controls |
|---|---|
| `REVERB_SERVER_PORT` | The port Reverb binds |
| `REVERB_PORT` | The port the browser connects to |

Diagnose a repeat with `netstat -ano | Select-String ":8081"` then `Get-Process -Id <pid>`.

## Configuration

`.env` holds the app credentials, generated by `reverb:install`. The `VITE_REVERB_*` mirrors are
what the browser bundle reads:

```
REVERB_APP_ID / REVERB_APP_KEY / REVERB_APP_SECRET
REVERB_HOST="localhost"
REVERB_PORT=8081
REVERB_SERVER_PORT=8081
REVERB_SCHEME=http

VITE_REVERB_APP_KEY="${REVERB_APP_KEY}"
VITE_REVERB_HOST="${REVERB_HOST}"
VITE_REVERB_PORT="${REVERB_PORT}"
VITE_REVERB_SCHEME="${REVERB_SCHEME}"
```

`BROADCAST_CONNECTION=reverb`. Channel authorisation lives in `routes/channels.php`, registered in
`bootstrap/app.php`.

Note the ordering trap: `BROADCAST_CONNECTION=reverb` with no credentials present makes *every*
artisan command fail, including the one that generates them. If the credentials are ever lost, set
the connection back to `log`, regenerate, then switch back.

## Events

Events implement `ShouldBroadcastNow` rather than `ShouldBroadcast`, so they fire inline instead of
waiting on a queue worker — a bid appearing a second late defeats the point.

Each event declares `broadcastAs()` to give a short, stable name. Without it the event name is the
fully-qualified class, and the client has to reconstruct the namespace to listen.

## Verified

The round-trip was proven before any feature was built on it: one event, two browser tabs, both
receiving it with an **identical server-generated timestamp** — confirming a single server event
fanned out, rather than each client rendering its own clock. The harness was deleted once it passed.
